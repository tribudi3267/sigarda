**Keputusan user (semua final):**
1. Kelas = **rombel** (mis. XI-3); kolom `profiles.kelas` tetap dipakai sebagai rombel.
2. **Ketat saat memilih penguji (ajukan), lunak saat mencatat hasil**: penguji lain boleh menggantikan, tercatat di riwayat ("menggantikan X").
3. Penugasan diatur **Admin saja** (tab di halaman Anggota); Pembina hanya melihat.
4. Berlaku **per tahun ajaran**; rombel tanpa penugasan kembali ke aturan lama (semua penguji) sampai Admin mengatur atau menyalin dari tahun lalu.
5. **Butir agama**: hanya Pembina yang agamanya SAMA dengan Penegak (Pembina punya `profiles.agama`). Bila tidak ada Pembina seagama: buat **surat pengantar** (cetak/PDF, QR + kode verifikasi) ke guru agama yang sesuai. QR menyatakan dokumen sah dan memuat: diterbitkan oleh siapa, dibuat oleh siapa, ditandatangani oleh siapa, plus data Penegak. Berlaku juga untuk tanda tangan Kartu SKU dan surat-surat lain kelak (bangun infrastruktur umum `dokumen_terbit`).
6. **Dewan hanya menguji butir Bantara**; butir Laksana khusus Pembina.
7. Pengecualian per Penegak: opsional (fase terakhir); user minta penjelasan skenario nyata (sudah dijelaskan: pindah rombel di tengah tahun, Pembina cuti/dinas panjang, konflik kepentingan/kerabat, pembimbing portofolio Garuda, rombel kosong).
Ikut dibuat: naik kelas + alumni, alihkan pengajuan, antrian kelas bersama, riwayat penugasan, beban penguji, lencana antrian, tombol WhatsApp (ingatkan penguji dan ingatkan Penegak), dashboard progres per rombel (Pembina dan Dewan), PWA, default dan saring per rombel (termasuk Raport Pembina).

**Desain (usulan saya):** semua aditif, tanpa deploy ulang Edge Function (tanda tangan fungsi tetap). Tabel `penugasan_rombel(tahun_ajaran, rombel, penguji_id)` + `penugasan_log` (append-only); helper server `sigarda.penguji_boleh(peserta, penguji, sku)` dipakai `sg_sku_ajukan` dan RPC `sg_penguji_pilihan(sku)` (daftar penguji sah + beban antrian, agar klien tidak menduplikasi aturan); `sg_sku_ajukan` menerima penguji NULL = antrian bersama rombel (penguji mengambil lewat "Mulai uji"); `sg_sku_alihkan` (Pembina/Admin, alasan wajib, riwayat); `sg_sku_catat_internal` menambah teks "menggantikan X" bila pencatat bukan penguji tujuan dan menolak Dewan pada butir LAK. Hasil guru agama luar: dicatat Pembina dengan `penguji_luar` (nama guru) + nomor surat (asumsi, perlu konfirmasi). `dokumen_terbit(token, jenis, nomor, peserta_id, dibuat_oleh, diterbitkan_oleh, penanda_tangan snapshot, payload jsonb, dicabut)` + perluasan `sg_verifikasi_token`. Alumni: kolom `profiles.alumni_pada`; dikeluarkan dari rekap/pilihan/antrian; QR verifikasi tetap sah. WA: nomor di tabel terpisah `kontak` dengan RLS ketat + RPC; tautan `wa.me` (tanpa API). PWA: manifest + ikon PNG + service worker kecil (tanpa cache API Supabase) + pesan "versi baru tersedia".
Catatan hukum untuk pengguna: QR = tanda tangan elektronik internal (bukan TTE tersertifikasi); surat ke pihak luar sekolah mungkin tetap butuh cap/tanda tangan basah.

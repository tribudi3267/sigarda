# SIGARDA (Gudep SMAN 1 Bukateja): panduan untuk Claude

Aplikasi web Sistem Informasi Garuda dan SKU Penegak. React 18 + Vite 5 + Tailwind 3; Supabase (Postgres + Auth + satu Edge Function). Situs: https://sigarda.smabukateja.sch.id/ (GitHub Pages, terbit otomatis saat `git push` ke `main`). Rincian fitur dan pemasangan ada di README.md; berkas ini hanya memuat yang perlu diketahui sebelum mengubah kode.

## Aturan kerja (dari pemilik proyek)
- **Semua balasan, komentar, teks layar, dan pesan commit dalam Bahasa Indonesia.** Pengguna adalah guru/Pembina Pramuka, bukan pemrogram.
- **Jangan commit atau push kecuali diminta.** Bila diminta: pesan commit diakhiri baris `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`; tulis pesan ke berkas lalu `git commit -F <berkas>` (PowerShell merusak pesan multibaris).
- Migrasi SQL dijalankan **pengguna** di SQL Editor Supabase; Edge Function di-deploy pengguna. Jangan mengetik PIN atau kata sandi asli. Uji di mode lokal dengan akun contoh.
- Isi instrumen penilaian (panduan penguji) **rahasia** dan tidak boleh masuk repositori. `.env.local` jangan di-commit.
- Sebelum menyatakan selesai: `npm run build` dan `npm run uji` harus lulus.
- Rencana pengembangan aktif ada di memori proyek (`ide-penugasan-penguji-per-kelas.md`): satu fase per sesi.

## Arsitektur (jangan dilanggar)
- **RLS hanya baca.** Semua penulisan lewat fungsi `sg_*` (`security definer`) yang memeriksa peran di server; fungsi bantu ada di skema `sigarda`. Klien tidak pernah menulis tabel langsung.
- **Sumber kebenaran skema: `supabase/sumber/inti.sql`** (panjang, gunakan Grep terarah, jangan dibaca utuh). `npm run skema` membuat `supabase/skema.sql` (jangan diedit tangan; hanya untuk database baru).
- **Database yang sudah berjalan diubah lewat migrasi aditif** `supabase/migrasi/*.sql` (idempoten, tanpa menghapus data). Susun dari blok bermarka di inti.sql dengan `scripts/migrasi/bantu.mjs` (contoh: `scripts/migrasi/2026-09-iuran.mjs`). Jangan mengulang migrasi lama sesudah yang lebih baru (beberapa menimpa fungsi yang sama). Dokumentasikan urutan di README, bagian "Memperbarui database yang sudah berjalan".
- Edge Function `supabase/functions/sigarda/index.ts`: login, akun, PIN, dan pencatatan hasil uji setelah PIN penguji diverifikasi. Ubah **isi** fungsi SQL tanpa mengubah tanda tangannya agar tidak perlu deploy ulang.
- Klien: `src/lib/api.js` satu-satunya pintu ke Supabase; `src/lib/mapDb.js` memetakan baris ke bentuk halaman; `src/context/AppContext.jsx` memuat state dan aksi; logika murni di `src/lib/*Logic.js` (dicerminkan dengan SQL dan dijaga pengujian); halaman di `src/pages`, komponen di `src/components`. Menu per peran di `src/App.jsx` (`buatNav`).
- **Identitas gudep dan pejabat (nama gudep, ambalan, nomor gudep, Pembina/Ka Gudep, Kamabigus, NTA) DIATUR ADMIN di menu "Data Gudep"**, bukan di kode: baca lewat `useGudep()` (komponen) atau `ambilGudep()` (non-React) dari `src/lib/gudepStore.js`; jangan mengimpor `GUDEP_BAWAAN` (`src/config.js`) di halaman (hanya nilai awal). Tersimpan di pengaturan `gudep.data` (`sg_gudep_simpan`, Admin); tanpa login hanya `sg_gudep_publik` (nama gudep, ambalan, sekolah, kota). Aturan isian: `src/lib/gudepLogic.js` (dijaga `uji/gudep.mjs`). Dokumen baru wajib memakai data ini untuk kop, kota, dan penanda tangan; blok tanda tangan dan stempel basah seragam = `src/components/BlokTtd.jsx` (jangan membuat blok sendiri; dijaga `uji/ttd.mjs`). **Pradana dan Pradani bukan bagian Data Gudep**: mereka anggota Dewan Ambalan berjabatan itu (`profiles.jabatan_dewan` pada akun Penegak, diatur Pembina/Admin lewat menu Kepengurusan atau `sg_anggota_jabatan_dewan_atur`; nama dan NTA dari akun; logika di `src/lib/dewanLogic.js`, dijaga `uji/jabatan-dewan.mjs`, `uji/dewan-penegak.mjs`). Ketua sidang = Pradana (`sigarda.ketua_sidang`, disalin ke catatan sidang; `sidang.nama_ketua/sebutan_ketua` hanya cadangan). Berita Acara Sidang bertoken QR (`sidang_dk.token/kode`, `sg_sidang_token`, dibuat saat pertama dicetak) diverifikasi lewat `sg_verifikasi_token/kode`.
- **Notifikasi dan PWA:** notifikasi dibuat oleh PEMICU di basis data (`sigarda.notif_*` pada `sku_progress`, `sesi_ujian_peserta`, `dokumen_terbit`; pengingat harian `sigarda.notif_pengingat` lewat pg_cron), bukan di tiap fungsi aksi; isi singkat dan TANPA hasil lulus/ulang. Tabel `notifikasi` (baca: pemilik), `push_langganan` dan `push_konfigurasi` (tanpa kebijakan baca; hanya fungsi). Web Push: pemicu statement-level `sigarda.push_antre` -> pg_net -> Edge Function TERPISAH `supabase/functions/notif-push/index.ts` (rahasia bersama `x-sigarda-rahasia`, VAPID; dites dengan `uji/palsu/web-push.mjs`); pemilik mengisi alamat dan kunci lewat `select sigarda.push_atur(...)`. Klien: `src/lib/pushClient.js` (semua akses API peramban, `env` dapat diganti untuk uji), `notifikasiLogic.js`, halaman `src/pages/Notifikasi.jsx`, menu Notifikasi + lencana (`LencanaMenu` di ui.jsx; jangan taruh elemen `sr-only` tanpa induk berposisi). **Keluar menghentikan push di perangkat itu** (keputusan privasi HP bersama; jangan diubah tanpa tanya). `public/sw.js` HANYA push dan klik notifikasi: TANPA fetch handler dan TANPA cache (dijaga `uji/notifikasi-klien.mjs`). `version.json` + `__BUILD_ID__` (vite.config.js) memunculkan ajakan "Muat ulang".
- **Jenis kelamin** (`profiles.jenis_kelamin` 'L'/'P', semua peran termasuk Admin): WAJIB untuk anggota baru (formulir dan setiap baris import; template punya kolom `jk` tepat sesudah Nama Lengkap), boleh kosong untuk anggota lama. Diisi lewat `sg_anggota_jk_atur` (Admin, atomik) SESUDAH akun dibuat, karena Edge Function `sigarda` tidak membawanya (jangan ubah tanda tangan `sg_profil_buat_internal`); anggota lama dilengkapi lewat tombol "Lengkapi jenis kelamin" (`LengkapiJenisKelaminModal`, `jenisKelaminLogic.js`, `jenisKelaminExcel.js`; dijaga `uji/jenis-kelamin.mjs`). Pengujian yang mengisi template menurut posisi kolom harus memakai posisi baru.
- **Status anggota dan naik kelas (fase 6a):** `profiles.status` 'aktif' | 'nonaktif' (tidak melanjutkan Pramuka, masih siswa) | 'alumni' (lulus), `status_pada`, `lulus_ta`. Nonaktif dan alumni HANYA DILIHAT dan dicetak: pemicu `sigarda.tolak_peserta_tak_aktif` pada tabel kegiatan (sku_progress, sku_riwayat, absensi_hadir, iuran, iuran_log, asisten_iuran, portofolio(_jurnal), sku_penilaian, raport, sesi_ujian_peserta) menolak penulisan apa pun lewat jalur mana pun (jangan menambah pengecekan status di tiap fungsi; tabel baru yang menyimpan `peserta_id` untuk kegiatan wajib diberi pemicu yang sama); fungsi aksi yang membatalkan pengajuan harus melakukannya SEBELUM mengubah status. Fungsi daftar kerja server (`sg_iuran_lembar`, `sg_absen_set_banyak`, dst.) menyaring `status = 'aktif'`. Klien: `daftarPeserta` (AppContext) = Penegak AKTIF, `daftarPesertaSemua` = semua (pencarian satu orang, halaman Anggota, filter Status); `terapkanFilter` memakai `filter.status` (bawaan 'aktif'; FilterBar `tampil` memuat 'status' untuk menampilkan pilihannya); daftar baru yang membaca `users` langsung wajib menyaring aktif (`(u.status ?? 'aktif') === 'aktif'`); `hanyaLihatSaya` menyembunyikan aksi tulis Penegak nonaktif/alumni. Naik kelas massal = `sg_naik_kelas(ta, data, terapkan)` (Admin; pratinjau lalu terapkan, semua atau tidak sama sekali, batch + log dapat dibatalkan lewat `sg_naik_kelas_batalkan`), satu orang = `sg_anggota_status_atur` (Pembina dan Admin; alumni hanya Admin). Isian bawaan dan aturan di `src/lib/naikKelasLogic.js` (dijaga `uji/naik-kelas-klien.mjs`, `uji/naik-kelas.mjs`). Halaman `NaikKelas.jsx` (menu Admin).
- Peran: Penegak (`peserta`; peran turunan Calon Bantara/Laksana/Garuda dihitung dari progres), Pembina (`penguji`), Admin Gudep (`admin`). **Dewan Ambalan = ATRIBUT akun Penegak (fase 6b)**: `profiles.jabatan_dewan` (isian bebas 2-60 karakter; Pradana dan Pradani unik dan berfungsi khusus) pada Penegak AKTIF; bukan akun terpisah. Server: `sigarda.pengurus()`/`dewan()` mengikutsertakan Penegak aktif berjabatan, `sigarda.bisa_menguji(id)` = Pembina, akun Dewan lama aktif, atau Penegak aktif berjabatan (jangan memeriksa `role = 'penguji'` langsung untuk hak menguji). Klien: `AppContext` punya `akun` (apa adanya) dan `user` (menurut tampilan): Penegak berjabatan memilih tampilan Penegak/Dewan (`BilahTampilan`, disimpan per akun di localStorage) dan dalam tampilan Dewan `user.role = 'penguji'`, `jabatan = 'Dewan Ambalan'` sehingga seluruh menu dan aturan penguji berlaku; `rombelLogic.js`: `penegakDewan`, `bisaMenguji`. `daftarPesertaSemua` bagi `user.role === 'peserta'` hanya berisi dirinya (RLS `baca_profil` memperlihatkan Penegak berjabatan kepada semua). Edge Function `sigarda` mengenali Penegak berjabatan (catat hasil, reset PIN). **Akun Dewan lama** (role penguji, jabatan Dewan Ambalan) tetap berfungsi sampai diarsipkan Admin (`sg_dewan_lama_arsipkan`, status nonaktif; klien menampilkan `LayarArsip`); UI tidak lagi membuat akun Dewan baru (server masih mengizinkan, demi uji dan akun lama). Kepengurusan: menu Kepengurusan (Pembina dan Admin), `sg_kepengurusan_terapkan(data, ganti, terapkan)` (pratinjau/terapkan atomik, `kepengurusan_log`), `sg_anggota_jabatan_dewan_atur` (Pembina dan Admin; jabatan kosong = cabut). Jabatan DICABUT OTOMATIS saat Penegak nonaktif/alumni lewat `sigarda.jabatan_dewan_lepas` (menghapus penugasannya, pengajuan 'diajukan' kembali ke antrian, tercatat); panggil fungsi itu bila menambah jalur yang menonaktifkan Penegak.
- **Kelas Penegak = rombel baku** `X-01..X-10`, `XI-01..XI-10`, `XII-01..XII-10` (`sigarda.rombel_sah`, cermin di `src/lib/rombelLogic.js`); server menolak selain itu saat buat akun/ubah, data lama ("X") dibiarkan sampai dirapikan lewat "Perbarui rombel". Penugasan (`sg_penugasan_atur/salin`, `sg_penugasan_peserta_atur`) diatur Pembina DAN Admin; guru agama tetap Admin. Klien mencerminkan: `pengujiPeranOk(users, peserta, penguji, poin, dokumen, { penugasan, penugasanPeserta })`, `pengujiSah`, hook `useKonteksMenilai`. Pembina punya `profiles.agama`; Dewan dan Admin tidak. **Fase 2a:** `dokumen_terbit` (umum; jenis `surat_pengantar_agama`, nomor dari `dokumen_urut` + `surat.format_nomor`, `sg_dokumen_surat_agama_terbit/cabut`) diverifikasi lewat `sg_verifikasi_token/kode`; surat = TEMPLATE untuk tanda tangan dan stempel BASAH (QR hanya bukti terbit); surat berlaku membuka hak Pembina tidak seagama mencatat butir agama yang tercantum (`sigarda.surat_agama_aktif`, cermin `suratAgamaAktif` di `src/lib/dokumenLogic.js`, dijaga `uji/dokumen.mjs`).

Persetujuan memanggil `sg_agenda_simpan` SENDIRI (fungsi memanggil fungsi, `auth.uid()` tetap pemanggil asli) dengan judul dari `sigarda.kegiatan_judul_bawaan(jenis)` dan `lewati_batas` HANYA true untuk jenis `'musyawarah'` bila tanggal usulan di atas/pada batas (jenis lain SELALU false — kalau selalu true, kolom itu jadi tidak berarti apa-apa lagi). `sg_kegiatan_ping(p_id)`: Pradana/Pradani mengingatkan ulang semua Pembina, dibatasi sekali per 24 jam lewat kolom `diping_pada`. Dua fungsi pengingat TERPISAH (keduanya dipanggil dari `notif_pengingat()`, dalam penanda blok KELIMA yang membungkus fungsi sama, kini bertumpuk lima lapis: Cadangan L4, Eskalasi L5, Agenda L6, Usulan Musyawarah L6b, Usulan Kegiatan Lain L6b): `sigarda.musyawarah_pengingat()` (TIDAK BERUBAH sejak rancangan awal — H-60 lalu tiap 14 hari bila `tahun_ajaran_kini()` belum punya entri `agenda` jenis musyawarah, TANPA batas atas) dan `sigarda.kegiatan_pengingat()` (10 jenis lain, tabel konfigurasi `(jenis, h_n, bulan1, bulan2)` inline lewat `sigarda.kegiatan_bulan_tanggal(tahun_ajaran, bulan)`; bila 2 bulan sasaran per tahun, dipakai yang PALING AWAL — bulan kedua tidak menambah pengingat baru karena yang pertama sudah berjalan tiap 14 hari sampai disetujui). Migrasi L6b JUGA menulis ulang `sg_agenda_simpan` (validasi `p_jenis` + badan yang memanggil `sigarda.pembina_saja()`) dan `sg_cadangan_admin()` (menambahkan `agenda` dan `kegiatan_usulan` yang tertinggal saat L6/L6b berjalan) — pola ini (migrasi baru menulis ulang fungsi tahap SEBELUMNYA yang badannya berubah demi dipakai ulang) akan terulang; sertakan blok fungsi lama yang berubah, bukan cuma blok fungsi baru. **Jebakan PL/pgSQL**: alias kolom pada subquery VALUES (`... as t(jenis, h_n, bulan1, bulan2)`) TIDAK BOLEH mencantumkan tipe data (`as t(jenis text, ...)` gagal parse) — beda dengan definisi `returns table(...)`. Dijaga `uji/kegiatan.mjs`, `uji/migrasi-kegiatan.mjs`.
- **Berkas Calon Garuda (tahap L7):** dari halaman Portofolio, tombol "Cetak / bagikan berkas" (Pembina dan Admin) menghimpun sampul+identitas, **Kartu Kemajuan SKU Bantara dan Laksana** (komponen `KartuSku` dari `src/components/DokumenSku.jsx`, DIPAKAI ULANG apa adanya, bukan dibuat baru), cek list 26 dokumen portofolio, dan jurnal ringkas jadi SATU dokumen cetak (`src/components/BerkasGaruda.jsx`: `BerkasGarudaDokumen` murni-props + `TampilanBerkasGaruda` pembungkus terautentikasi). **PDF tetap pola print-CSS lama** (`window.print()`, TANPA library PDF) — `BerkasGarudaDokumen` BUTUH `useApp()` untuk `{ progress, users }` (dipakai `KartuSku`) padahal halaman publik di bawah tidak punya sesi login: solusinya `KonteksApp` (raw React context, diekspor `src/context/AppContext.jsx` khusus untuk ini dan untuk `uji/halaman-6b.mjs`) DIPASANG ULANG dengan nilai dari tautan berbagi, BUKAN `AppProvider` sungguhan — pola ini akan terulang untuk kebutuhan serupa (menggabungkan komponen cetak yang sudah ada ke halaman publik). **Tautan berbagi baca-saja** (`?berkas=<token>`, tanpa login, dicek di `App.jsx` SEBELUM `AppProvider` — pola sama dengan `?v=<token>` verifikasi tapi BEDA TUJUAN: token ini memberi akses BACA ISI LENGKAP, bukan cuma ringkasan keaslian, jadi tabel `garuda_berkas_token` SENGAJA TIDAK diberi kebijakan RLS apa pun (sama seperti `sertifikat_tingkat`: hanya lewat fungsi `security definer`) dan SENGAJA TIDAK ikut `sg_cadangan_admin()` (diperlakukan seperti kredensial, bukan bukti keaslian). Satu token AKTIF per peserta (indeks unik parsial); regenerasi (`sg_garuda_token_buat`) mencabut yang lama, TANPA kedaluwarsa otomatis (hanya `sg_garuda_token_cabut` manual). Fungsi bantu `sigarda.garuda_berkas_json(peserta_id)` (SQL murni, dipanggil BERSAMA oleh `sg_garuda_berkas_baca` yang sudah login dan `sg_garuda_token_baca` yang publik — satu sumber data, dua jalur akses) mengembalikan baris MENTAH `sku_progress`/`sku_riwayat`/`portofolio`/`portofolio_jurnal` (BUKAN bentuk terpetakan) supaya klien memetakannya lewat `susunProgress`/`susunPortofolio` yang SAMA dengan halaman biasa (`src/lib/mapDb.js`: `susunBerkasGaruda`) — tampilannya otomatis konsisten tanpa duplikasi logika pemetaan. Hak: HANYA `sigarda.pembina_atau_admin()` (BUKAN Dewan Ambalan, sengaja lebih ketat daripada menilai portofolio sehari-hari yang memakai `sigarda.bisa_menguji()`) boleh membuka/membuat/mencabut — kirim data ke pihak luar organisasi dianggap lebih sensitif. **Jebakan migrasi (tabel BARU, ditemukan lewat uji `periksa-pemasangan`)**: PostgreSQL/Supabase memberi hak penuh bawaan ke tabel baru lewat `alter default privileges` (lihat `supabase/lokal/stub.sql`), jadi migrasi yang menambah tabel WAJIB `revoke all on public.<tabel_baru> from anon, authenticated;` segera sesudah `create table` (persis seperti migrasi `sertifikat_tingkat`/`sesi_ujian` lama) — kalau tidak, tabel itu KELIHATAN sama di database baru vs migrasi tapi sebenarnya beda hak akses (skema baru sudah "disterilkan" oleh `revoke all on all tables in schema public from anon, authenticated` di akhir `inti.sql`, migrasi tidak). Dijaga `uji/garuda.mjs`, `uji/migrasi-garuda.mjs`.

## Perintah
- **Mode uji tanpa PIN (L1):** `npm run dev:lokal` lalu buka `/?masuk=<akun>` (admin, pembina, dewan, 10231, 10008 = Penegak berjabatan Sekretaris, 10007) untuk masuk tanpa mengetik PIN dan tanpa wajib ganti PIN; `?data=penuh` memakai basis data lokal terpisah berisi data sekolah penuh (`src/lokal/sekolahPenuh.js`: 700 Penegak, 150 alumni, ±27 ribu progres; dibuat sekali, ~1 menit); `?ulang=1` membuat ulang. Kode: `parameterUji.js` (dimuat halaman masuk) dan `masukCepat.js` (PIN dan api; hanya dimuat `bootLokal`, TIDAK boleh masuk build produksi; dijaga `uji/mode-uji.mjs` yang membangun produksi dan mencari penanda). Gunakan ini untuk memeriksa halaman asli di browser pane (jangan mengetik PIN).
- **`npm run periksa`** membuat `supabase/demo/periksa_pemasangan.sql` dari skema terbaru: jalankan sesudah `npm run skema` setiap `inti.sql` berubah (pengujian `periksa-pemasangan` gagal bila usang).
- `npm run dev:lokal` (PGlite di browser, akun contoh tertera di layar login; wajib ganti PIN saat masuk pertama; "Kembalikan data contoh" bila skema lokal usang). `npm run build`. `npm run skema`.
- **`npm run uji`** menjalankan semua pengujian di `uji/` (Postgres sungguhan lewat PGlite). Sebagian: `npm run uji -- iuran api`. `PENUH=40` menampilkan 40 baris terakhir keluaran. Tiap berkas mencetak `ok`/`GAGAL` dan satu baris RINGKASAN.
- Pengujian migrasi memakai skema lama dari git: `baru('git:<commit>')` = `supabase/skema.sql` pada commit itu (pakai commit TEPAT sebelum perubahan). Contoh: `uji/migrasi-gudep.mjs` (`git:709a260`); uji migrasi lama membandingkan dengan skema commit sesudahnya, bukan `skema.sql` terbaru. Akhir baris disamakan LF sebelum membandingkan md5 fungsi (checkout Windows = CRLF). Di git worktree, `npm run uji` memakai `node_modules` repo induk; untuk `dev:lokal` di worktree perlu `server.fs.allow` ke repo induk (konfigurasi sementara, jangan di-commit). Pengujian `instrumen` dilewati kecuali `ISI_INSTRUMEN=<jalur SQL isi instrumen>`.
- Tambah pengujian baru sebagai `uji/<nama>.mjs` (impor `../src/...`; jalur kerja `process.cwd()`; berkas sementara di `.uji/tmp`).

## Konvensi tampilan (sudah disetujui pengguna; jaga konsisten untuk fitur baru)
- Menu samping kiri berkelompok (md ke atas); menu bawah ponsel yang dapat digeser dengan panah emas berdenyut; ikon menu aktif berkilau emas (`.ikon-aktif`). Kilau emas memakai kelas yang sudah ada (`.glow-emas`, `.glow-emas-tetap`, `.panah-geser-*` di `src/index.css`); jangan membuat gaya cahaya baru.
- Navigasi panjang di ponsel: bilah melayang `sticky top-[3.75rem]` di bawah header, dropdown menumpang (`absolute`), target gulir `scroll-mt-36 lg:scroll-mt-24`; di layar lebar berupa kolom samping sticky (contoh: `src/pages/Materi.jsx`).
- Deretan lencana/chip harus **satu baris** di semua lebar (sisanya disembunyikan di balik tombol `+N`): `src/components/TerkaitButir.jsx`.
- Tabel lebar dibungkus `overflow-x-auto` (kini otomatis `position: relative` di `index.css`). Elemen `absolute` (mis. `sr-only`) yang lolos dari pembungkus melebarkan halaman dan membuat menu bawah bergeser di ponsel.
- Uji halaman baru di lebar 320, 375, dan 768px: ukur `document.documentElement.scrollWidth` dengan `html,body{overflow-x:visible !important}` disuntik sementara; nilainya harus sama dengan lebar layar. Emulator browser pane menahan animasi dan screenshot-nya terpotong: ukur lewat DOM, minta pengguna memeriksa kilau di HP.
- Peran, dan hak, ditegakkan di server; tampilan hanya menyembunyikan tombol.

## Lingkungan Windows / PowerShell
- Ubah kode dengan alat Edit/Write, bukan string PowerShell (backtick dan `${}` rusak). `&&` tidak tersedia. Segarkan PATH di tiap panggilan: `$env:Path=[System.Environment]::GetEnvironmentVariable('Path','Machine')+';'+[System.Environment]::GetEnvironmentVariable('Path','User')`.
- Menghentikan dev server: cari proses pada port lalu `Stop-Process` (dev:lokal memakai `--port 5199 --strictPort`).

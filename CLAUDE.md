# SIGARDA (Gudep SMAN 1 Bukateja): panduan untuk Claude

Aplikasi web Sistem Informasi Garuda dan SKU Penegak. React 18 + Vite 5 + Tailwind 3; Supabase (Postgres + Auth + satu Edge Function). Situs: https://sigarda.smabukateja.sch.id/ (GitHub Pages, terbit otomatis saat `git push` ke `main`). Rincian fitur dan pemasangan ada di README.md; berkas ini hanya memuat yang perlu diketahui sebelum mengubah kode.

## Aturan kerja (dari pemilik proyek)
- **Semua balasan, komentar, teks layar, dan pesan commit dalam Bahasa Indonesia.** Pengguna adalah guru/Pembina Pramuka, bukan pemrogram.
- **Jangan commit atau push kecuali diminta.** Bila diminta: pesan commit diakhiri baris `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`; tulis pesan ke berkas lalu `git commit -F <berkas>` (PowerShell merusak pesan multibaris).
- Migrasi SQL dijalankan **pengguna** di SQL Editor Supabase; Edge Function di-deploy pengguna. Jangan mengetik PIN atau kata sandi asli. Uji di mode lokal dengan akun contoh.
- Isi instrumen penilaian (panduan penguji) **rahasia** dan tidak boleh masuk repositori. `.env.local` jangan di-commit.
- Sebelum menyatakan selesai: `npm run build` dan `npm run uji` harus lulus.
- Rencana pengembangan aktif ada di memori proyek (`ide-penugasan-penguji-per-kelas.md`): satu fase per sesi.

## Arsitektur (jangan dilanggar)
- **RLS hanya baca.** Semua penulisan lewat fungsi `sg_*` (`security definer`) yang memeriksa peran di server; fungsi bantu ada di skema `sigarda`. Klien tidak pernah menulis tabel langsung.
- **Sumber kebenaran skema: `supabase/sumber/*.sql`** = 33 berkas bernomor per modul (`00-awal`, `1x-tabel-*`, `3x-bantu-*`, `40-rls-baca`, `5x/6x-aksi-*`, `70-hak-akses-katalog`; peta di `supabase/sumber/README.md`), dirakit urut nama tanpa pemisah oleh `scripts/sumber.mjs` (`bacaInti`). Cari modul dengan Grep terarah, ubah HANYA berkas modulnya, jangan menyusun ulang urutan (urutan = urutan definisi; tabel baru di berkas tabel yang sesuai, fungsinya di berkas bantu/aksi modul yang sama). Berkas baru harus bernomor unik (dijaga `uji/sumber-skema.mjs`, yang juga menggagalkan bila `skema.sql` usang). `npm run skema` membuat `supabase/skema.sql` (jangan diedit tangan; hanya untuk database baru).
- **Database yang sudah berjalan diubah lewat migrasi aditif** `supabase/migrasi/*.sql` (idempoten, tanpa menghapus data). Susun dari blok bermarka di sumber (penanda dapat melintasi berkas karena `ambil` bekerja pada rakitan utuh) dengan `scripts/migrasi/bantu.mjs` (contoh: `scripts/migrasi/2026-09-iuran.mjs`). Jangan mengulang migrasi lama sesudah yang lebih baru (beberapa menimpa fungsi yang sama). Dokumentasikan urutan di README, bagian "Memperbarui database yang sudah berjalan".
- Edge Function `supabase/functions/sigarda/index.ts`: login, akun, PIN, dan pencatatan hasil uji setelah PIN penguji diverifikasi. Ubah **isi** fungsi SQL tanpa mengubah tanda tangannya agar tidak perlu deploy ulang.
- Klien: `src/lib/api.js` satu-satunya pintu ke Supabase; `src/lib/mapDb.js` memetakan baris ke bentuk halaman; `src/context/AppContext.jsx` memuat state dan aksi; logika murni di `src/lib/*Logic.js` (dicerminkan dengan SQL dan dijaga pengujian); halaman di `src/pages`, komponen di `src/components`. Menu per peran di `src/App.jsx` (`buatNav`).
- **Cermin klien-server (P4):** aturan yang ada di klien DAN server didaftar di `docs/cermin-klien-server.md` (baca sebelum menambah aturan yang dicerminkan). Predikat peran di klien HANYA lewat `src/lib/hakLogic.js` (`pembinaAtauAdmin`, `pembinaSaja`, `pengurus`, `dewan`, `pradanaAtauPradani`); jangan menulis ulang `role === 'admin' || (... 'Pembina')` di halaman (dijaga `uji/paritas-hak.mjs`, yang juga membandingkan predikat itu, `tingkatSelesai/layakGaruda`, rombel/tahun ajaran, batas Musyawarah, dan jenis kegiatan dengan SQL). "Hari ini" di klien = WIB (`format.hariIni`), sama dengan `sigarda.hari_ini()`; jangan memakai `new Date().toISOString().slice(0, 10)` (UTC) atau tanggal perangkat untuk logika tanggal. Cermin baru wajib punya perbandingan langsung ke SQL, bukan hanya nilai tetap di klien.
- **Skalabilitas klien (P3):** `ambilSemua` (api.js) membaca halaman ke-2 dst. serempak per gelombang `HALAMAN_SEREMPAK` (halaman pertama sendirian, tanpa hitung baris); JANGAN mengembalikannya ke berurutan. `muatProgress(null, { riwayat: false })` melewatkan `sku_riwayat` (tabel terbesar) saat masuk: `entry.riwayat` kosong sampai `pastikanRiwayat(pesertaId)` (AppContext; dipanggil `SkuChecklist`) memuat riwayat satu Penegak, dan penyegaran menyeluruh memuat ulang riwayat Penegak yang sudah dibuka (`riwayatDimuat`). Komponen baru yang membaca `entry.riwayat` untuk Penegak lain harus memanggil `pastikanRiwayat` juga. Halaman selain beranda/dashboard dimuat malas (`React.lazy` di App.jsx, dibungkus `BatasHalaman`); halaman baru ikut pola itu (dijaga `uji/skala-klien.mjs`). Ukur dampak dengan `npm run profil` (model jaringan; anggaran JS awal 150 kB gzip).
- **Identitas gudep dan pejabat (nama gudep, ambalan, nomor gudep, Pembina/Ka Gudep, Kamabigus, NTA) DIATUR ADMIN di menu "Data Gudep"**, bukan di kode: baca lewat `useGudep()` (komponen) atau `ambilGudep()` (non-React) dari `src/lib/gudepStore.js`; jangan mengimpor `GUDEP_BAWAAN` (`src/config.js`) di halaman (hanya nilai awal). Tersimpan di pengaturan `gudep.data` (`sg_gudep_simpan`, Admin); tanpa login hanya `sg_gudep_publik` (nama gudep, ambalan, sekolah, kota). Dokumen baru wajib memakai data ini untuk kop, kota, dan penanda tangan; blok tanda tangan dan stempel basah seragam = `src/components/BlokTtd.jsx` (jangan membuat blok sendiri; dijaga `uji/ttd.mjs`). **Pradana dan Pradani bukan bagian Data Gudep**: mereka anggota Dewan Ambalan berjabatan itu (`profiles.jabatan_dewan` pada akun Penegak, diatur Pembina/Admin lewat menu Kepengurusan atau `sg_anggota_jabatan_dewan_atur`; nama dan NTA dari akun; logika di `src/lib/dewanLogic.js`, dijaga `uji/jabatan-dewan.mjs`, `uji/dewan-penegak.mjs`). Ketua sidang = Pradana (`sigarda.ketua_sidang`, disalin ke catatan sidang; `sidang.nama_ketua/sebutan_ketua` hanya cadangan). Berita Acara Sidang bertoken QR (`sidang_dk.token/kode`, `sg_sidang_token`, dibuat saat pertama dicetak) diverifikasi lewat `sg_verifikasi_token/kode`.

Web Push: pemicu statement-level `sigarda.push_antre` -> pg_net -> Edge Function TERPISAH `supabase/functions/notif-push/index.ts` (rahasia bersama `x-sigarda-rahasia`, VAPID; dites dengan `uji/palsu/web-push.mjs`); pemilik mengisi alamat dan kunci lewat `select sigarda.push_atur(...)`. - **Jenis kelamin** (`profiles.jenis_kelamin` 'L'/'P', semua peran termasuk Admin): WAJIB untuk anggota baru (formulir dan setiap baris import; template punya kolom `jk` tepat sesudah Nama Lengkap), boleh kosong untuk anggota lama. ## Perintah
- **Mode uji tanpa PIN (L1):** `npm run dev:lokal` lalu buka `/?masuk=<akun>` (admin, pembina, dewan, 10231, 10008 = Penegak berjabatan Sekretaris, 10007) untuk masuk tanpa mengetik PIN dan tanpa wajib ganti PIN; `?data=penuh` memakai basis data lokal terpisah berisi data sekolah penuh (`src/lokal/sekolahPenuh.js`: 700 Penegak, 150 alumni, ±27 ribu progres; dibuat sekali, ~1 menit); `?ulang=1` membuat ulang. Kode: `parameterUji.js` (dimuat halaman masuk) dan `masukCepat.js` (PIN dan api; hanya dimuat `bootLokal`, TIDAK boleh masuk build produksi; dijaga `uji/mode-uji.mjs` yang membangun produksi dan mencari penanda). Gunakan ini untuk memeriksa halaman asli di browser pane (jangan mengetik PIN).
- **`npm run catatan-rilis`** (P5) menyusun daftar migrasi SQL baru dan Edge Function yang berubah terhadap `origin/main`; CI memasangnya sebagai komentar tunggal pada tiap PR (`.github/workflows/catatan-rilis.yml`). **Migrasi baru wajib didaftarkan di README** (butir di bagian "Memperbarui database yang sudah berjalan", urutan daftar = urutan menjalankan; dijaga `uji/catatan-rilis.mjs`). Sebelum menggabungkan PR yang punya migrasi/Edge Function, ingatkan pemilik menjalankannya lebih dulu (situs terbit otomatis saat merge). Deploy Edge Function tetap manual oleh pemilik (butuh token sensitif bila diotomatiskan; belum diputuskan).
- **`npm run periksa`** membuat `supabase/demo/periksa_pemasangan.sql` dari skema terbaru: jalankan sesudah `npm run skema` setiap sumber skema berubah (pengujian `periksa-pemasangan` gagal bila usang).
- `npm run dev:lokal` (PGlite di browser, akun contoh tertera di layar login; wajib ganti PIN saat masuk pertama; "Kembalikan data contoh" bila skema lokal usang). `npm run build`. `npm run skema`.
- **`npm run uji`** menjalankan semua pengujian di `uji/` (Postgres sungguhan lewat PGlite). Sebagian: `npm run uji -- iuran api`. `PENUH=40` menampilkan 40 baris terakhir keluaran. Tiap berkas mencetak `ok`/`GAGAL` dan satu baris RINGKASAN.
- Pengujian migrasi memakai skema lama yang DISIMPAN di repositori: `baru('git:<commit>')` membaca snapshot `supabase/riwayat/<hash7>.sql.gz` (= `supabase/skema.sql` pada commit itu), BUKAN riwayat git, jadi tetap jalan pada clone dangkal/rebase. **Migrasi baru: sebelum menulis ujinya, jalankan `node scripts/simpan-skema-lama.mjs <hash commit tepat sebelum migrasi>` (atau `--dari-uji`)**; `uji/skema-lama.mjs` gagal bila ada hash yang dirujuk uji tanpa snapshot, atau snapshot yatim. Contoh: `uji/migrasi-gudep.mjs` (`git:709a260`); uji migrasi lama membandingkan dengan skema commit sesudahnya, bukan `skema.sql` terbaru. Akhir baris disamakan LF sebelum membandingkan md5 fungsi (checkout Windows = CRLF). Di git worktree, `npm run uji` memakai `node_modules` repo induk; untuk `dev:lokal` di worktree perlu `server.fs.allow` ke repo induk (konfigurasi sementara, jangan di-commit). Pengujian `instrumen` dilewati kecuali `ISI_INSTRUMEN=<jalur SQL isi instrumen>`.
- Tambah pengujian baru sebagai `uji/<nama>.mjs` (impor `../src/...`; jalur kerja `process.cwd()`; berkas sementara di `.uji/tmp`).

## Konvensi tampilan (sudah disetujui pengguna; jaga konsisten untuk fitur baru)
- Menu samping kiri berkelompok (md ke atas); menu bawah ponsel yang dapat digeser dengan panah emas berdenyut; ikon menu aktif berkilau emas (`.ikon-aktif`). Kilau emas memakai kelas yang sudah ada (`.glow-emas`, `.glow-emas-tetap`, `.panah-geser-*` di `src/index.css`); jangan membuat gaya cahaya baru.
- Navigasi panjang di ponsel: bilah melayang `sticky top-[3.75rem]` di bawah header, dropdown menumpang (`absolute`), target gulir `scroll-mt-36 lg:scroll-mt-24`; di layar lebar berupa kolom samping sticky (contoh: `src/pages/Materi.jsx`).
- Deretan lencana/chip harus **satu baris** di semua lebar (sisanya disembunyikan di balik tombol `+N`): `src/components/TerkaitButir.jsx`.
- Tabel lebar dibungkus `overflow-x-auto` (kini otomatis `position: relative` di `index.css`). Elemen `absolute` (mis. `sr-only`) yang lolos dari pembungkus melebarkan halaman dan membuat menu bawah bergeser di ponsel.
- Uji halaman baru di lebar 320, 375, dan 768px: ukur `document.documentElement.scrollWidth` dengan `html,body{overflow-x:visible !important}` disuntik sementara; nilainya harus sama dengan lebar layar. Emulator browser pane menahan animasi dan screenshot-nya terpotong: ukur lewat DOM, minta pengguna memeriksa kilau di HP.
- Peran, dan hak, ditegakkan di server; tampilan hanya menyembunyikan tombol.

## Lingkungan Windows / PowerShell
- Ubah kode dengan alat Edit/Write, bukan string PowerShell (backtick dan `${}` rusak). `&&` tidak tersedia. Segarkan PATH di tiap panggilan: `$env:Path=[System.Environment]::GetEnvironmentVariable('Path','Machine')+';'+[System.Environment]::GetEnvironmentVariable('Path','User')`.
- Menghentikan dev server: cari proses pada port lalu `Stop-Process` (dev:lokal memakai `--port 5199 --strictPort`).
